# 失敗案例、系統缺陷與不確定性分析 (FAILURE_ANALYSIS)

## 1. 模型假警報根因分析（3,840 場受控試驗）

由 `experiments/TEST_EXECUTION_LOG.csv` 逐場檢查 326 筆 False Positives：
- `TRANSIENT_SPIKE`：**320 / 320 (100%)**
- `HIGH_FREQ_OSCILLATION`：**4 / 320 (1.25%)**
- `NORMAL_STABLE`：**1 / 320 (0.31%)**
- `BAD_QUALITY_FROZEN`：**1 / 320 (0.31%)**（在品質惡化前之第 10–14 分鐘隨機波動偶然觸發）

### 根因機制
1. **外推錨點敏感性**：`Fcst_h = x_now + Slope * h` 直接使用瞬時讀值 `x_now`。在 `+0.30 * span` 單分鐘突波出現當下，`x_now` 已接近上限且 5 分鐘局部均差拉升 `Slope > 0`，導致 `Fcst_30` 單點越界。
2. **L6 單向鎖存效應**：`L6` 採「升級即時、降級延遲 3 次」設計，一旦單分鐘突波觸發 `T-30`，即鎖存 3 分鐘，使任何後段外部計數器無法在當下濾除單點尖峰。
3. **消融修正方向**：將連續確認機制移至 L6 鎖存前 (`raw_onset = 2`)，於 480 場驗證集 (`ablation_sensitivity.json`) 將 `FAR` 由 `25.62%` 降至 `6.88%` (`theta=2.0`) 與 `1.25%` (`theta=2.5`)。

## 2. 系統層級歷史缺陷與修復狀態

1. **線上部署版 (`https://pcw-scada-system.vercel.app/`) 狀態不一致缺陷**：
   - `SimulatorEngine` 僅於整分邊界重算預測，且 `ModbusMonitor` 修改設定未主動重算，造成 `1.72 bar` 越限時 Alarm Center 顯示 `HIGH` 而 System Prediction 仍顯示 `NORMAL`。
   - **已於重構版系統 (`PCW_SCADA_Final_Project/system/`) 修復並通過 pytest 與端到端驗證**。
2. **`N10 > 2.0` 數學不可達盲區**：
   - 對稱雜訊使 `M60 >= 30` 時，`N10 <= 2.0`，嚴格大於永遠不成立；統一改為 `N10 >= theta`。
3. **10 分鐘以上持續基準偏移失效問題**：
   - 原 L2 僅檢查斜率 `|Slope|*30`，當基準偏移超過 10 分鐘後 `P` 與 `R` 皆穩定於新基準造成斜率趨近於零而誤解除；重構版加入 `|mean(C) - BaseAvg60| >= g%*(H-L)` 水準偏移條件，確保 10 分鐘以上持續偏移穩定維持預警。

## 3. 研究限制與不確定性

1. 除 `PT-1` (480 分鐘) 參考資料外，全廠 320 測點之橫向比較仍來自受控合成生成器，尚未完成多座真實晶圓廠長時間歷史事件之外部校準。
2. 480 分鐘 `PT-1` 參考資料因包含反覆未越限波動，單點逐列 Precision 為 `10.17%–11.76%`，顯示單憑壓力時間序列在無製程工況狀態旗標時仍受負載變動影響。
