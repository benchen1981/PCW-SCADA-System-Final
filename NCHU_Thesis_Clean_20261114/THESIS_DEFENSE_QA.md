## 1. 模型與演算法設計類

### Q1: 為什麼選擇「因果雙滑動視窗 (Past-Only)」而非近年熱門的深度學習模型（如 LSTM、Transformer、PatchTST）？
**答辯要點**：
1. **微秒級極致即時性**：先進晶圓廠全廠涵蓋 160 支壓力計、80 支流量計與 80 支差壓計，SCADA 輪詢週期為 1 秒。本研究之因果線性外推與閉式解到限時間（TTL）在 Apple M5 實機上，單測點推論僅需 **13.54 $\mu$s**，全廠 320 測點批次推論僅 **4.56 ms**（Table 9）。深度學習模型參數量龐大，在單純工業 CPU 上難以保證微秒級確定性延遲。
2. **零樣本（Zero-shot）冷啟動與抗概念漂移**：半導體機台製程配方經常更動，深度學習黑盒子模型高度依賴大量歷史故障標註樣本，且極易因製程切換產生過擬合或誤報。本文所提之雙滑動視窗即時計算動態基線 $B_t=[t-70, t-10)$，無需繁瑣重訓即可自我調適。
3. **物理可解釋性與可審計性**：晶圓廠運轉不容許黑盒子隨機警報。本模型輸出具備封閉形式之最小平方法（OLS）斜率與 95% 預測區間，廠務工程師能一眼判讀水力阻抗變化趨勢，完全符合半導體工業的高可靠度規範。

### Q2: 到限時間（Time-To-Limit, TTL）的數學封閉解是如何推導的？若斜率為負或接近零時如何防止除以零？
**答辯要點**：
1. 在第 3.2.3 節中，針對觀測視窗 $C_t$ 內的資料點，以時間為自變量進行普通最小平方法回歸，得到即時壓力估計方程式：
   $$\hat{P}(t + \tau) = \hat{\beta}_1 \tau + \hat{\beta}_0$$
2. 當檢測到上升漂移（$\hat{\beta}_1 > 0$）時，預測到達工程上限 $P_{\text{limit}}$ 的剩餘時間定義為：
   $$\text{TTL}(t) = \frac{P_{\text{limit}} - \hat{\beta}_0}{\hat{\beta}_1}$$
3. **數值穩定性防護**：本模型設定最小顯著斜率門檻 $\epsilon = 10^{-4}$ bar/min。若 $|\hat{\beta}_1| < \epsilon$ 或斜率方向朝安全區內側收斂（例如下降至下限之上），系統自動將 $\text{TTL}$ 設為 $\infty$，並將狀態保持在 NORMAL，徹底避免浮點數除以零或無效預警。

### Q3: 為什麼多層狀態機需要設計連續兩點確認（$K=2$）與連續三點解除鎖存（Release Hold = 3）？
**答辯要點**：
1. **工業雜訊濾除**：無塵室內閥門開度調節或水泵微小暫態切換常伴隨短暫的單點壓力毛刺（Spike）。若採用單次觸發（$K=1$），全廠 1,920 場試驗中會產生多達 163 場虛警（誤報率高達 25.47%）。
2. **代價極小的抗噪防線**：導入 $K=2$（連續兩點確認）後，虛警數由 163 場大幅降至 26 場，**虛警濾除率達 84.05%**，誤報率壓低至 4.06%，而平均處置提前量僅微幅減少 0.76 分鐘（由 10.60 分鐘降為 9.84 分鐘），仍保有充足處置時間（Table 5）。
3. **防止震盪（Debounce）**：Release Hold = 3 保證當水壓恢復時，必須連續 3 個採樣點均位於安全門檻內才解除警報，避免狀態機在臨界值附近頻繁跳躍（Chattering）。

## 2. 資料集與因果邊界類

### Q4: 論文強調的「因果式約束（Past-Only Constraints）」具體在程式碼中如何落實？傳統研究常見的因果洩漏是什麼？
**答辯要點**：
1. **傳統因果洩漏（Look-ahead Bias）**：許多學術文獻在資料預處理時，採用全域 Min-Max 標準化（使用測試集的最大最小值），或使用對稱平滑濾波器（如取 $t-k$ 到 $t+k$ 的中央移動平均）。這等同於在 $t$ 時刻「偷看了未來的資料」，造成離線評估 F1 接近完美，但在線上 SCADA 即時部署時全面崩潰。
2. **本研究的嚴格 Past-Only 架構**：
   - 特徵提取所使用的時間序列資料索引嚴格限制在 $\tau < t$。
   - 歷史基準窗 $B_t = [t-70, t-10)$ 與近期觀測窗 $C_t = [t-10, t)$ 嚴格終止於當前時間步長 $t$。
   - 滾動均值 $\mu_{B,t}$ 與標準差 $\sigma_{B,t}$ 僅由過去 60 分鐘計算，動態偏離比 $N_{10}$ 亦僅由過去 10 分鐘計算，保證線上回放與即時推論完全等價。

### Q5: 為什麼在第 4.3.4 節中，真實歷史資料回放的 F1-Score 僅有 0.1818？這是否代表模型失效？
**答辯要點**：
1. **學術誠實揭露**：此為刻意進行之「非受控極端消融試驗（Table 6）」，目的在於驗證未校準靜態門檻在多機台交互干擾下的局限性。
2. **工業物理本質**：真實晶圓廠運轉中，機台配方切換與生產線排程導致管網流量與負載頻繁大幅階躍，若缺乏機台生產排程（MES）狀態對齊，全廠採用單一靜態固定門檻會將常態調度誤判為水壓漂移。
3. **印證本研究貢獻**：正因為非受控環境下靜態門檻的低落表現，更加證明本論文提出的「動態滾動基線」與「多層狀態確認」不可或缺，為後續導入製程工況感知的多模態預警指明了方向。

## 3. 實驗設計與消融分析類

### Q6: 論文中的 1,920 場試驗是如何構成的？固定隨機種子的意義為何？
**答辯要點**：
1. **嚴謹實驗矩陣**：全廠共 160 支壓力計（PT-01 至 PT-160），每支測點均受試 12 種故障與干擾情境（S01 至 S12），共計：
   $$160 \times 12 = 1,920 \text{ 場試驗}$$
   - 正樣本（故障漂移）：S01~S08，共 $160 \times 8 = 1,280$ 場。
   - 負樣本（無故障干擾）：S09~S12，共 $160 \times 4 = 640$ 場。
2. **科學可重現性**：所有高斯白噪聲、測點特定微小擾動與漂移起始時刻均由固定隨機種子 `Seed = 20261111` 生成，並在程式碼中固定，確保任何第三方研究人員重新執行試驗腳本時，皆能輸出完全一致的數值結果與混淆矩陣。

## 4. 半導體廠務與 SCADA 工程實務類

### Q8: 半導體晶圓廠 PCW 系統中四大參數分組（G1～G4）的劃分依據為何？
**答辯要點**：
1. **微影製程組（G1, EUV/ArFi）**：光學反射鏡與雷射源對熱形變極為敏感，容許水壓波動最小，常態水壓設定為 3.00 bar，警報區間最為狹窄（LO: 2.80 bar, HI: 3.20 bar）。
2. **乾式蝕刻與薄膜沉積組（G2, Dry Etch / CVD / PVD）**：電漿反應室射頻熱源負載龐大，冷卻水需求流量高，常態設定為 3.50 bar。
3. **擴散爐管與離子植入組（G3, Diffusion / RTP / Implant）**：高溫熱爐管冷卻需求，常態設定為 2.80 bar。
4. **化學機械研磨與廠務輔助組（G4, CMP / Wet Bench / Utility）**：大流量且水壓公差相對寬鬆，常態設定為 2.50 bar。

### Q9: 本研究的 Web SCADA 系統採用何種通訊架構與安全機制？
**答辯要點**：
1. **工業通訊層**：採用標準 Modbus TCP 協定（15020 埠），水壓與流量數據均以 IEEE 754 32 位元浮點數（FLOAT32 CDAB 位元組順序）存取於保持暫存器（Holding Registers）中（Table 10）。
2. **推論服務層**：後端採用高併發 Python FastAPI 搭配非同步事件迴圈，每秒由 Modbus 輪詢 320 個暫存器，並以 SQLite WAL（Write-Ahead Logging）持久化所有推論狀態。
3. **前端視覺化層**：採用 Vite + React 與 WebSocket 雙向推播，全廠 160 測點的即時狀態、TTL 到限時間、滾動基線與狀態機階梯變化，延遲低於 100 毫秒，具備高度響應性。

### Q10: 為什麼本論文不宣稱「為晶圓廠節省數百萬美元」或「在商業產線零停機」？
**答辯要點**：
1. **恪守學術誠信底線**：本研究驗證是在高保真數位孿生與實機 Modbus SCADA 測試台上完成，並非在實際量產 12 吋商用晶圓廠中進行破壞性斷水測試（任何實際斷水都會導致數千萬台幣的晶圓報廢）。
2. **嚴謹的工程表述**：因此，本論文嚴謹且實事求是地將成果界定為「提供平均 9.84 分鐘之處置提前量」、「在 1,920 場試驗中達成 98.01% 精確率與 100% 召回率」，不作未經工業現場簽署之經濟效益誇大宣稱，完全符合頂尖國立大學碩士論文之學術風骨。
